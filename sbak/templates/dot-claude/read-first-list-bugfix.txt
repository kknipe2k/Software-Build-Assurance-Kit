# Read-first orientation list for BUG_FIX projects (operating_mode: bug_fix).
#
# Loaded by .claude/hooks/session-start-read-first.cjs when project-config.md
# carries `operating_mode: bug_fix`. The hook composes the read-first list from
# BOTH axes: operating_mode picks this FAMILY; role picks the
# bias-guard variant. With only this family file present, every bug_fix session
# (work Phases A/B, verifier Phase C) resolves THIS list.
#
# WHY THIS LIST IS SHORT — and deliberately so:
#   A bug fix is NOT a small greenfield build. There is no spec to satisfy, no
#   scope matrix, no ranked backlog, no milestone plan. Forcing those reads on a
#   bug fix is pure orientation overhead. This list omits them ON PURPOSE and
#   focuses the session on the affected surface:
#     - spec/project-spec.md      → omitted (no spec; the existing code is the spec)
#     - docs/scope.md             → omitted (no milestones)
#     - docs/backlog.md           → omitted (no ranked feature backlog)
#     - docs/build-prompts/M*.md  → omitted (no Phase docs; BUGFIX-PHASE-DOC drives)
#
# WHAT IT KEEPS — the affected surface and the impact analysis:
#   - the bug doc (docs/bugfix/<bug-id>.md): observed vs expected behavior, the
#     reproducer, the impact-analysis test list (Phase A output), the fix summary.
#   - the playbook's bug_fix workflow (§3.7) and the do-not-commit discipline.
#
# The bootstrap rewrites `docs/bugfix/<bug-id>.md` below to the actual bug id.
# Cap still applies (read_first_cap in project-config.md); list in priority order.
