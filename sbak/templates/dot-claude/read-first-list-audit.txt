# Read-first orientation list for AUDIT projects (operating_mode: audit).
#
# Loaded by .claude/hooks/session-start-read-first.cjs when project-config.md
# carries `operating_mode: audit`. The hook composes the read-first list from
# BOTH axes: operating_mode picks this FAMILY; role picks the
# bias-guard variant. Every audit pass + challenge runs as `role: verifier`
# (audit IS verification) and resolves THIS one list — the per-pass persona,
# dimension, and checklist ride on the pasted <audit_pass_prompt>, NOT on a new
# per-pass list (that is the whole point: modes add lists, not
# role values).
#
# WHY THIS LIST IS SHORT — and deliberately so:
#   An audit is NOT a greenfield build. There is no spec to satisfy, no scope
#   matrix, no ranked backlog, no milestone plan — the EXISTING CODEBASE is the
#   spec. Forcing those reads on an audit is pure orientation overhead. This list
#   omits them ON PURPOSE and focuses every pass on the Phase-S setup artifacts:
#     - spec/project-spec.md      → omitted (no spec; the existing code is the spec)
#     - docs/scope.md             → omitted (audit has phases, not milestones)
#     - docs/backlog.md           → omitted (no ranked feature backlog)
#     - docs/build-prompts/M*.md  → omitted (no Phase docs; REVIEW_PLAN.md drives)
#
# WHAT IT KEEPS — the structural map, the triage, the plan, and the ledger:
#   - docs/audit/INVENTORY.md   : the complete structural map (every file present
#                                 or EXCLUDED + rationale — G_AUDIT_S1).
#   - docs/audit/TRIAGE.md      : per-dimension CRITICAL / MODERATE / SCAN.
#   - docs/audit/REVIEW_PLAN.md : the tier-conditional pass plan (which dimensions
#                                 run, which get challenged).
#   - docs/audit/findings-ledger.md : the append-only consolidated findings (so a
#                                 later pass / consolidation sees what already
#                                 landed and doesn't re-litigate it).
#   - the playbook's audit workflow (§3.8) and the do-not-commit discipline.
#
# Cap still applies (read_first_cap in project-config.md); list in priority order.

# Entry grammar (M30.G lazy orientation): <path>  when: <boundary>  [- why]. Boundaries:
# session-start (inlined by the hook) | host (loaded by Claude Code itself) | stage-open (checked by
# approve-red) | verify (/verify step 1) | closeout (/closeout step 1) | phase-0/1/3 (bootstrap) | on-demand.
